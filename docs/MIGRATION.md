# Migration: web app → Android app

**Decision: Android first. No Mac available, so iOS is deferred, not designed out.**

Everything below keeps the codebase iOS-ready — the platform seam is built now, the iOS half is filled in when a Mac or a cloud builder is available. Nothing here has to be redone later.

---

## Target

| | |
|---|---|
| Shell | **Capacitor** (Android now, iOS later from the same repo) |
| Build | **Vite**, vanilla JS, no framework |
| Storage | `@capacitor/preferences` behind the existing `store` wrapper |
| Speech | `@capacitor-community/speech-recognition` + `@capacitor-community/text-to-speech` |
| Backend | none in v1 |
| Distribution | Google Play, closed testing → production |

**Not a rewrite.** The app works; the job is to give it a native shell, a real project structure, and native speech. React Native or Flutter would mean rebuilding Klara, the chalkboard, six themes, Lesson 1 and the notes system for no user-visible gain.

## Phase 0 · Repo (half a day)

```
sprak/
  index.html            # the shell; #app lives here
  src/
    styles.css          # was head.html
    content.js  core.js  screens1-4.js  avatar.js  lesson1.js  verbs.js  notes.js
    platform/           # NEW — the native seam
      speech.js  storage.js
    main.js             # imports in the pinned order
  tests/                # the existing *.mjs suites
  android/              # generated by Capacitor
  docs/  CLAUDE.md
```

- Git repo, `main` branch, conventional commits.
- Convert the concatenation into ES module imports **in the same order** as `build.sh`. The order is load-bearing; keep the comment explaining why.
- `vite build` replaces `build.sh`. Keep a `npm run build:single` that still produces the one-file version — it is useful for sharing and for the artifact.

**Done when:** `npm run dev` serves the app and every existing test suite passes against it.

## Phase 1 · Capacitor + Android (1 day)

```bash
npm i @capacitor/core @capacitor/cli @capacitor/android
npx cap init Sprak com.sprak.app --web-dir=dist
npx cap add android
npm run build && npx cap sync android
npx cap open android        # opens Android Studio
```

- `applicationId`: `com.sprak.app` — decide now, it cannot change after the first Play upload.
- Set `minSdk` to 24 or higher.
- Add the microphone permission to `AndroidManifest.xml`: `android.permission.RECORD_AUDIO`.
- Splash screen and adaptive icon from the Sprak mark.

**Done when:** it installs and runs on a real Android phone, and every screen renders correctly at that device's width.

## Phase 2 · The speech seam (2–3 days) — the real work

The whole app talks to speech through **seven functions** in `core.js` and `lesson1.js`. Move them behind `src/platform/speech.js`:

```js
export const Speech = {
  isNative,                       // Capacitor.isNativePlatform()
  speak(text, rate),              // TTS
  stop(),
  hasRecognition(),               // capability, per platform
  requestPermission(),
  listenOnce({ lang, onResult, onError }),
  listenContinuous({ … }),
};
```

- Browser path: the current Web Speech code, unchanged.
- Native path: the Capacitor plugins.
- Every existing caller keeps its signature. `speak`, `sayEnDe`, `teacherSay`, `micLine`, `l1MicOne`, `hasMic`, `l1HasMic` become thin wrappers.

**While you are in here, fix the four speech defects from `KNOWN_ISSUES.md`** — they are cheaper to fix during the port than after:

- pause recognition while Klara speaks (the app currently transcribes its own voice and awards the tick)
- handle every error code, not just `not-allowed`
- stop the restart loop on `network` / `audio-capture`
- cancel speech and timers in `go()`

**A note on Klara's voice.** Native TTS uses whatever German voice the device has, so she will sound different from phone to phone. If one consistent Klara matters, pre-generate her fixed lines as MP3 files and ship them as assets — the curriculum is fixed, so this is a one-time cost. Decide before the store listing, because her voice is part of the product.

**Done when:** microphone works on a real Android device, ticks are awarded correctly, and denying the permission produces a clear message rather than silence.

## Phase 3 · Storage (half a day)

Replace `localStorage` inside the existing `store` wrapper with `@capacitor/preferences`. The wrapper already exists, so this is contained.

Fix at the same time:

- surface save failures instead of swallowing them
- debounce and cap the writing-screen draft, which currently re-serialises all of `S` on every keystroke
- validate the shape of the loaded state and version the schema
- persist Lesson 1 progress per step, not only at the end

**Done when:** progress survives force-quit, and a corrupted store recovers rather than bricking the app.

## Phase 4 · Native polish (2–3 days)

- Safe areas — `env(safe-area-inset-*)`, already partly used for the nav bar.
- Android **back button**: `@capacitor/app` `backButton` listener wired to `go()` history. Without it, back exits the app mid-lesson.
- Keep the screen awake during a lesson if the mic is listening.
- Handle audio focus: pause TTS on an incoming call.
- Accessibility pass from `DESIGN_SYSTEM.md`: 48dp touch targets, contrast, keyboard/TalkBack reachability.
- Test at 320px width and at 200% font scale.

---

## Phase 5 · Play Store (2 days of work, 14 days of waiting)

**Start the testing clock as early as you can — it is the longest pole.**

- Google Play developer account: **$25, one time**.
- Personal accounts need **12 testers running the app for 14 consecutive days** before production is unlocked. Recruit the testers during Phase 2, not at the end.
- Needed: app icon, feature graphic, 2–8 phone screenshots, short and full description, content rating questionnaire, data-safety form, and a **privacy policy URL** (short and honest: no account, no collection, everything on device).
- Sign the release, upload an **AAB** (not APK), promote closed → open → production.

**Realistic:** 3–4 weeks to public release full-time, 6–8 weeks part-time, with the 14-day window overlapping the later phases.

## iOS, when a Mac exists

Nothing above blocks it. The remaining work is:

- `npx cap add ios`, icons, `NSMicrophoneUsageDescription` and `NSSpeechRecognitionUsageDescription` in `Info.plist`
- Fill in the iOS branch of `platform/speech.js` — **required**, because the Web Speech API does not work inside WKWebView and `webkitSpeechRecognition` is still exposed there, so it fails silently ([WebKit bug 239816](https://bugs.webkit.org/show_bug.cgi?id=239816)). Without the native plugin the microphone is dead on iPhone while appearing to work.
- Apple Developer Program: **$99/year**.
- If no Mac by then: **Codemagic** or **Ionic Appflow** build and sign iOS from this repo in the cloud.

Because the seam is built in Phase 2, iOS is roughly a week, not a rewrite.
